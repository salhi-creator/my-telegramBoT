# Telegram Bot

A Telegram bot built with Node.js and TypeScript. The bot uses Telegram webhooks to receive messages, Redis for caching, and an instruction file to control the bot's behavior.

---

## How It Works

The bot uses a **webhook architecture** instead of continuously polling Telegram.

The communication flow is:

```text
┌──────────────┐
│    User      │
└──────┬───────┘
       │
       │ Message
       ▼
┌──────────────┐
│   Telegram   │
└──────┬───────┘
       │
       │ HTTP POST
       ▼
┌──────────────┐
│   Webhook    │
│    Server    │
└──────┬───────┘
       │
       ▼
┌──────────────┐
│  Bot Logic   │
└──────┬───────┘
       │
       ├──────────────► Redis
       │
       ├──────────────► instructions.txt
       │
       ▼
┌──────────────┐
│ AI / Response │
│   Handling    │
└──────┬───────┘
       │
       │ sendMessage
       ▼
┌──────────────┐
│   Telegram   │
└──────┬───────┘
       │
       ▼
┌──────────────┐
│    User      │
└──────────────┘
```

### In simple terms

1. The user sends a message to the Telegram bot.
2. Telegram creates an `Update`.
3. Telegram sends that update to the server through the configured webhook.
4. The server processes the update.
5. The bot uses its instructions and required data to determine a response.
6. Redis is used where cached data is required.
7. The server sends the response back to Telegram.
8. Telegram delivers the response to the user.

# Requirements

Before running the bot, you need:

* Node.js
* npm
* A Telegram bot
* A Telegram Bot API token
* A Redis instance
* A publicly accessible HTTPS webhook in production
* `ngrok` for local webhook development

# Environment Variables

Create a `.env` file in the root directory.

```env
TELEGRAM_BOT_TOKEN=your_telegram_bot_token

REDIS_URL=your_redis_connection_url

REDIS_LANG_CACHE=your_redis_language_cache

PORT=3000
```

The exact variable names must match the configuration used by the application.

## `TELEGRAM_BOT_TOKEN`

The token generated by Telegram's **BotFather**.

```env
TELEGRAM_BOT_TOKEN=your_token_here
```

This allows the application to communicate with the Telegram Bot API.

**Never commit the real token to GitHub.**

---

## `REDIS_URL`

The connection string used to connect the application to Redis.

```env
REDIS_URL=your_redis_url
```

---

## `REDIS_LANG_CACHE`

The credential/configuration used by the language cache.

```env
REDIS_LANG_CACHE=your_secret_here
```

Keep this value private.

**Do not put the real Redis credentials in this README.**

---

## `PORT`

The port on which the local server runs.

```env
PORT=3000
```

If your application uses another port, use that port instead.


# Changing the Bot's Behaviour

The bot's behavior is controlled by:

```text
instructions.txt
```

If you want to change **how the bot behaves or responds**, modify this file.

You normally do **not** need to modify the TypeScript source code just to change the bot's personality or instructions.

For example, `instructions.txt` might contain instructions such as:

```text
You are a helpful Telegram assistant.

Keep your responses concise.

Be friendly when communicating with users.

Follow the application's rules when responding.
```

You can change the instructions to modify things such as:

* Personality
* Tone
* Response style
* Rules
* Restrictions
* How specific situations are handled
* Formatting
* Other behavioral instructions

### Behavior vs functionality

There is an important distinction:

```text
instructions.txt
        │
        ▼
What the bot should do
and how it should behave
```

while:

```text
Source code
    │
    ▼
What the bot is technically
capable of doing
```

If you want to change the bot's behavior, start with `instructions.txt`.

If you want to add a completely new capability, you will generally need to modify the application code.

# Telegram Webhook

Telegram needs a public URL where it can send incoming bot updates.

During development, the application runs on your local machine:

```text
http://localhost:3000
```

The problem is that Telegram cannot directly access your computer's `localhost`.

This is why **ngrok** is used.

---

# Using ngrok for Local Development

Install and authenticate ngrok if you haven't already.

Once the application is running locally, expose its port with:

```bash
ngrok http 3000
```

If your server uses another port, replace `3000`.

For example:

```bash
ngrok http 3000
```

ngrok will provide a public HTTPS URL similar to:

```text
https://abc123.ngrok-free.app
```

The connection now looks like this:

```text
Telegram
   │
   │ HTTPS
   ▼
https://abc123.ngrok-free.app
   │
   │ ngrok tunnel
   ▼
http://localhost:3000
   │
   ▼
Your Node.js server
```

This allows Telegram to communicate with your local development server.

---

# Connecting Telegram to the Server

After starting ngrok, Telegram's webhook must be configured to point to the ngrok URL.

Telegram provides the `setWebhook` Bot API method for this.

The general format is:

```text
https://api.telegram.org/bot<BOT_TOKEN>/setWebhook?url=<WEBHOOK_URL>
```

For example:

```text
https://api.telegram.org/botYOUR_BOT_TOKEN/setWebhook?url=https://abc123.ngrok-free.app/telegram/webhook
```

You can configure it using `curl`:

```bash
curl -X POST "https://api.telegram.org/botYOUR_BOT_TOKEN/setWebhook" -d "url=https://abc123.ngrok-free.app/telegram/webhook"
```

Replace:

```text
YOUR_BOT_TOKEN
```

with your actual Telegram bot token.

Also replace:

```text
/telegram/webhook
```

with the webhook route implemented by the application if your project uses a different route.

---

# Webhook Request

Once the webhook is configured, Telegram sends an HTTP `POST` request whenever something happens with the bot.

For example, when a user sends:

```text
/start
```

Telegram sends an `Update` to your server.

Conceptually, it looks like:

```json
{
  "update_id": 123456789,
  "message": {
    "message_id": 42,
    "chat": {
      "id": 123456789,
      "type": "private"
    },
    "text": "/start"
  }
}
```

The server receives this request and processes the update.

The important point is:

> **Your server does not continuously ask Telegram for messages. Telegram pushes messages to your server through the webhook.**

---

# Sending a Response

After processing the update, the bot sends a message back through the Telegram Bot API.

Telegram's API follows this structure:

```text
https://api.telegram.org/bot<BOT_TOKEN>/<METHOD>
```

For sending a message, the method is:

```text
sendMessage
```

Conceptually:

```text
POST
https://api.telegram.org/bot<BOT_TOKEN>/sendMessage
```

with data such as:

```json
{
  "chat_id": 123456789,
  "text": "Hello!"
}
```

The complete communication therefore looks like:

```text
User
 │
 │ "Hello"
 ▼
Telegram
 │
 │ POST Update
 ▼
Webhook
 │
 ▼
Bot Logic
 │
 ├── instructions.txt
 │
 ├── Redis
 │
 └── AI / application logic
 │
 ▼
sendMessage
 │
 ▼
Telegram
 │
 ▼
User
```

# Checking the Webhook

You can check the webhook currently registered for your bot using:

```bash
curl "https://api.telegram.org/botYOUR_BOT_TOKEN/getWebhookInfo"
```

Telegram will return information about the current webhook.

This is useful when debugging:

* Wrong webhook URL
* Server not running
* ngrok tunnel stopped
* Incorrect webhook route
* Telegram unable to reach the server
* Webhook delivery errors

---

# Important: ngrok URLs Change

When using a temporary ngrok URL, the public address can change.

For example, today:

```text
https://abc123.ngrok-free.app
```

and later:

```text
https://xyz789.ngrok-free.app
```

If the URL changes, Telegram is still pointing to the old webhook.

You therefore need to register the new webhook URL again:

```bash
curl -X POST "https://api.telegram.org/botYOUR_BOT_TOKEN/setWebhook" -d "url=https://NEW-NGROK-URL/telegram/webhook"
```

---

# Production

For production, you normally don't need ngrok.

Instead, deploy the server to a public host with a permanent HTTPS domain.

For example:

```text
Telegram
    │
    ▼
https://bot.example.com/telegram/webhook
    │
    ▼
Production Server
    │
    ├── Bot Logic
    ├── Redis
    └── AI / Services
```

Then register the production webhook:

```bash
curl -X POST "https://api.telegram.org/botYOUR_BOT_TOKEN/setWebhook" -d "url=https://bot.example.com/telegram/webhook"
```

# Security

Never commit secrets to GitHub.

Your `.gitignore` should include:

```gitignore
.env
.env.*
!.env.example
```

Create an `.env.example` file containing placeholders:

```env
TELEGRAM_BOT_TOKEN=
REDIS_URL=
REDIS_LANG_CACHE=
PORT=3000
```

This allows other developers to understand which environment variables are required without exposing your credentials.

If a Telegram token or Redis credential has accidentally been committed to Git history, **rotate the credential** rather than simply deleting the file.

# Troubleshooting

### The bot does not respond

Check:

1. Is the Node.js server running?
2. Is ngrok running?
3. Is the ngrok URL correct?
4. Is Telegram's webhook pointing to the current ngrok URL?
5. Is the webhook path correct?
6. Is the Telegram bot token valid?
7. Is Redis connected?

Check the webhook:

```bash
curl "https://api.telegram.org/botYOUR_BOT_TOKEN/getWebhookInfo"
```

---

### ngrok is running but Telegram does nothing

Remember that starting ngrok only creates the tunnel.

You still need to tell Telegram where to send updates:

```text
Telegram
   │
   │ "Where should I send updates?"
   ▼
setWebhook
   │
   ▼
https://your-ngrok-url/your-webhook-route
```

## Summary

The bot is based around a simple webhook-driven architecture:

```text
                 Telegram
                    │
                    │ Webhook
                    ▼
              Node.js Server
                    │
          ┌─────────┼─────────┐
          ▼         ▼         ▼
   instructions    Redis     AI/Logic
       .txt
          │         │         │
          └─────────┼─────────┘
                    ▼
                Response
                    │
                    │ Telegram API
                    ▼
                 Telegram
                    │
                    ▼
                  User
```

For local development:

```text
npm run dev
      ↓
ngrok http 3000
      ↓
setWebhook
      ↓
Telegram → ngrok → localhost → bot
```

For production:

```text
Telegram → HTTPS domain → production server → bot
```

The main rule for modifying the project is:

> **Change `instructions.txt` when you want to change the bot's behavior. Change the source code when you want to change what the bot can actually do.**
